# 게임 엔진

`game/`는 Android UI·저장소에 의존하지 않는 Kotlin/JVM 코드입니다. 문제의 생성·진행·판정과 10문제 사이클을 담당합니다. 학습하기 화면의 정식 게임과 세 유형 연습에 연결되어 있습니다. 정식 게임의 영구 저장·복구와 AI 결정 연결은 `data/`의 Room Repository가 담당하며 `difficulty/`와 `ai/`가 다음 난이도를 계산합니다.

## 문제 생성

`ProblemGenerator.generate(type, conditions, previousTarget)`가 불변 `MemoryProblem`을 만듭니다. 난수와 문제 ID 공급자를 주입할 수 있습니다. 기본 ID는 UUID이며, 교체한 공급자도 문제마다 고유 ID를 반환해야 합니다.

| 유형 | v1 콘텐츠 | 생성기 버전 |
| --- | --- | --- |
| 색 | 파랑·주황·초록·보라의 좌우 두 칸 조합, 순서 포함 16가지 | `color-pair-v1` |
| 그림 | 원·사각형·삼각형·별·하트·달·꽃·집·나무·물고기·사과·컵·열쇠·우산·종·자동차 | `picture-symbol-v1` |
| 숫자 | 10~99의 두 자리 숫자 | `two-digit-number-v1` |

비슷한 색 16개를 늘리는 대신 네 색의 구성을 구분합니다. 같은 색 두 칸도 구분선과 동일한 크기를 유지하고, 좌우 순서는 기기 언어와 무관하게 고정합니다. `MemoryItemView`가 Canvas로 직접 작성한 16개 그림과 색 구성·숫자를 그립니다. 모든 콘텐츠에 읽기 설명을 제공합니다. 시니어의 색 구분과 그림 인지 사용성은 실물 기기 검증이 필요합니다.

모든 유형은 4·6·9·12·16개 보기를 지원합니다. 정답을 하나 포함하고 나머지는 중복 없이 추출한 뒤 섞습니다. 모델 생성 시 보기 ID·내용 중복, 정답 누락, 유형 혼합, 개수 불일치를 거부합니다. 보기는 복사한 읽기 전용 목록으로 보존합니다.

중단 문제를 교체할 때 기존 조건과 `previousTarget`을 전달하면 다른 대상을 생성합니다. Repository는 이전 문제를 무효 이력으로 유지하고 새 문제를 저장합니다. 시드 대신 실제 대상·보기 순서·생성기 버전과 조건 전체를 보존합니다.

## 진행과 시간

`GameRound(problem, clock)`는 한 문제에만 사용하며 ViewModel의 단일 이벤트 처리 경로에서 호출합니다. Android 연결 시 `SystemClock.elapsedRealtime()`을 시계로 공급합니다. 날짜/시각이나 UI tick 횟수로 풀이 시간을 계산하지 않습니다.

| 상태 | 시작·종료 조건 |
| --- | --- |
| READY | 대상이 표시된 후 `onMemoryShown()` 호출로 기억 시작 |
| MEMORY | 기억 제한 도달 또는 `next()`로 대상 숨김 요청·대기 시작 |
| WAIT | 설정된 대기가 모두 지나면 OPTIONS_PENDING |
| OPTIONS_PENDING | 보기 렌더링 대기. 실제 표시 후 `onOptionsShown()`으로 풀이 시작 |
| SOLVE | 정답·세 번째 오답·풀이 제한 도달로 종료 |
| FINISHED | 결과 확정. 이후 입력·tick·중단으로 결과를 변경하지 않음 |

`state` 조회는 시간을 진행시키지 않습니다. 화면 소유자는 보이는 동안 `tick()`을 호출하고 결과를 StateFlow에 전달합니다. `onMemoryShown()`과 `onOptionsShown()`의 중복 호출은 시계를 재시작하지 않습니다. 콜백은 해당 문제 인스턴스에 연결하고 문제 교체 시 이전 콜백과 타이머를 취소합니다.

기억 종료의 늦은 tick은 실제 관측 노출 시간을 기록하고 그때부터 대기를 모두 적용합니다. 대기 및 보기 준비 시간은 풀이 시간에서 제외합니다. UI에서는 상태 변경을 즉시 렌더링해야 하며 실제 프레임과 콜백 시점은 화면 PR에서 검증합니다.

풀이 제한은 `null`이면 무제한이고, 값이 있으면 15~40초입니다. 모든 답변은 처리 시 단조 시각으로 마감을 먼저 확인합니다. 제한 직전의 정답은 허용하고, 제한 시각 이상이면 tick이 없었어도 시간 초과입니다. 늦게 처리된 종료의 경과 시간은 실제 관측값을 유지하며 제한값으로 덮어쓰지 않습니다.

## 시도·결과·중단

- `answer(problemId, optionId)`로 선택합니다. 다른 문제 ID, 존재하지 않는 보기, 풀이 전·종료 후 입력은 시도로 세지 않습니다.
- 틀린 보기는 비활성 ID 목록에 포함합니다. 같은 오답의 재입력은 시도 횟수를 늘리거나 타이머를 초기화하지 않습니다. 1·2·3회차 중 정답이면 성공, 서로 다른 오답 세 번이면 실패입니다.
- 각 선택에는 콘텐츠·정오·풀이 시작 이후 누적 시간·단조 시각을 남깁니다. 첫 선택 정오/시간과 최종 정오/전체 시간을 구분합니다. 아무 선택 없이 시간 초과라면 첫 선택 시간은 `null`입니다.
- 미완료 문제의 `interrupt()`는 어느 단계에서든 `INTERRUPTED`, `valid=false`로 끝냅니다. 이 결과는 성적·유형별 10문제 묶음에 포함하면 안 됩니다. 완료된 결과는 중단으로 무효화하지 않습니다.
- 백그라운드 이벤트는 숨겨진 시간에 대해 tick을 재생하지 말고 중단으로 처리합니다. 프로세스 종료는 엔진 객체가 사라지므로 Room에 저장된 진행 문제를 새 프로세스에서 무효 처리하는 복구 절차가 필요합니다.

## 검증과 다음 연결

기존 게임/사이클 JUnit 테스트 45개는 세 유형×다섯 보기 수×100시드의 1,500개 문제, 시간 경계·중복 입력·중단과 10문제 완료·4/3/3 순환을 확인합니다. 추가 난이도·밴딧 테스트와 실제 파일 DB·화면 테스트가 학습/보상 연결·마이그레이션·복원·16개 보기를 검증합니다. 최신 전체 개수와 실행 기록은 [TEST_REPORT.md](TEST_REPORT.md)에 있습니다.

### 현재 화면 연결

- 학습하기의 게임 시작은 종합 4/3/3 배정을 섞고, 세 연습 버튼은 같은 유형 10문제를 구성합니다. 정식 완료 종합 사이클의 DB 집계를 기준으로 네 문제 유형을 순환합니다. 연습은 이 집계와 저장에서 제외합니다.
- `TrainingViewModel`이 상태를 StateFlow로 제공하고, `TrainingScreen`이 생명주기가 RESUMED이고 일시정지 메뉴가 닫혀 있을 때만 tick을 실행합니다. 표시 단계 진입 후 프레임을 거친 콜백으로 시계를 시작합니다. 일시정지 메뉴는 대상을 즉시 숨기고 미완료 문항을 중단하며, 시스템 뒤로가기도 이 메뉴를 엽니다.
- 홈 이동·백그라운드·Activity 재생성은 미완료 문제를 중단합니다. 이어하기에서 같은 유형·조건의 새 대상으로 대체하며 완료 문제 수를 유지합니다. 이전 내비게이션 화면의 늦은 이벤트는 새 사이클을 중단하지 않도록 세션 ID를 확인합니다.
- 10번째 문제 뒤 실제 선택 결과로 전체·유형별 첫 선택 정답과 최종 정답을 표시합니다. 정식 기록은 학습 현황에도 반영됩니다. 진행 종료는 사이클을 STOPPED로 남기며 완료 기록을 삭제하지 않습니다.
- ViewModel의 직렬 이벤트 큐는 입력 당시 단조 시각을 보존하며 Room 커밋 후 화면 결과를 공개합니다. 저장 오류는 재시도 화면으로 안내하고 마지막 커밋에서 복구합니다.
- `SessionCheckpoint`와 `GameRound.restore`는 저장된 완료/중단 결과와 10개 슬롯 각각의 조건을 복구합니다. 이전 프로세스의 타이머 시작점을 재사용하지 않으며 중단 문항만 새로 생성합니다. 현재 문제의 조건을 다른 유형 슬롯에 복사하지 않습니다.
- `startFormal`은 현재 세 유형의 난이도를 세션 생성에 전달하며 한 게임 안에서는 동결합니다. 유형별 유효 10개가 모여 만들어진 AI 결정은 사이클 완료/명시적 종료 후에만 적용합니다. 연습은 초기 조건과 메모리 상태만 사용합니다.
- 보기 9/12/16개는 그림 영역을 카드 전체로 확장하고 태블릿 높이에 맞춰 배치합니다. 태블릿 기본 글자에서 16개와 풀이 시간 표시가 한 화면에 들어갑니다. 작은 화면/글자 200%는 가로·세로 스크롤로 접근하며 풀이 시간은 스크롤 중에도 진행됩니다.
