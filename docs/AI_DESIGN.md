# 난이도·AI 설계

상태: `difficulty/`와 `ai/`의 순수 Kotlin 규칙 및 Room v2 실게임 연결을 구현했습니다. 기준은 [SPEC.md](SPEC.md) 7~14절입니다. 수치 예제는 [RULE_EXAMPLES.md](RULE_EXAMPLES.md), 실행 결과는 [TEST_REPORT.md](TEST_REPORT.md)에 있습니다. 가상 입력은 알고리즘 확인용이며 인지 효과 검증 결과가 아닙니다.

## 통계와 후보

`difficulty/`는 같은 유형·같은 조건의 유효 10문제에서 통계, 실행 가능한 후보와 복원을 계산합니다. `ai/`는 허용된 후보 중 하나를 선택하고 적용 이후의 결과로 학습합니다. 두 패키지는 순수 Kotlin의 결정적 계산이며 시계·난수에 의존하지 않습니다. 게임 엔진에서 시계·난수를 주입해 입력을 검증합니다.

조건은 `memoryLimitMs`, `waitMs`, `optionCount`, nullable `solveLimitMs`의 불변 스냅샷입니다. 기억은 5~20초, 대기는 3~10초, 선택지는 4/6/9/12/16, 유한 풀이 제한은 15~40초입니다. 제한 없음은 `null`입니다.

| 값 | 모집단·계산 |
| --- | --- |
| C | 유효 10문제 중 첫 선택 정답 수. 선택 전 시간 초과는 첫 선택 정답이 아님 |
| M | 첫 선택 정답 문제의 실제 기억 화면 노출 시간 평균. ‘다음’ 사용 여부와 무관 |
| A | 최종 정답 문제의 선택지 표시부터 정답까지 누적 풀이 시간 평균 |
| W | 최종 정답 문제의 Σ(시도 횟수 × 누적 풀이 시간) / 최종 정답 문제 수 |

실패·시간 초과는 C의 분모 10에 포함하지만 A/W에서는 제외합니다. 연습·무효 문항은 묶음에 들어가지 않습니다. 분모가 0인 평균은 `null`이며 0초로 대체하지 않습니다.

시간은 정수 밀리초로 저장하고 명세가 요구한 위치에서만 초로 반올림합니다. 양수 0.5초는 올림입니다. 평균을 먼저 정수 초로 바꾸지 않고 W 자체도 반올림하지 않습니다. 엄격한 `<` 경계는 합계·개수 기반으로 비교합니다.

| C | 결정 |
| --- | --- |
| 0~1 | 고정 전체 복원 |
| 2~3 | 고정 부분 복원 |
| 4~6 | 고정 유지 |
| 7~8 | KEEP + 실행 가능한 ADJUST_MEMORY/ADJUST_SOLVE 중 밴딧 선택 |
| 9~10 | 실행 가능한 ADJUST_MEMORY/ADJUST_SOLVE 중 밴딧 선택. 없으면 고정 유지 |

조건이 같은 ‘변경 후보’는 제외하지만 C=7~8의 KEEP는 유지합니다. C=9~10에서 변경할 수 없어 유지하는 것은 밴딧 선택으로 집계하지 않습니다.

기억 후보는 C=7~9에서 `round(M)`, C=10에서 `round(M)-1`을 5~20초로 제한하고 현재보다 짧을 때만 생성합니다. 별도의 감소 폭 제한은 없습니다.

풀이 후보는 제한 없음에서 40초 도입입니다. 제한이 있고 C=7~8이면 `W < Ts + round(Ts/2)`를 통과해야 하며 `P=round(A)+2`가 현재 Ts보다 짧아야 합니다. C=9~10이면 W와 관계없이 `P=Ts-5`입니다.

| P와 현재 조건 | 풀이 후보 결과 |
| --- | --- |
| P > 15 | 풀이 제한을 P초로 변경 |
| P ≤ 15, 선택지 < 16 | 선택지를 한 단계만 늘리고 풀이 제한 해제 |
| P ≤ 15, 선택지=16, 대기 < 10 | 제한 15, 대기 min(10, 현재+1)초 |
| P ≤ 15, 선택지=16, 대기=10 | 제한 15. 이미 15초라면 변경 후보 없음 |

풀이 후보를 선택했을 때만 전환하며 기억 제한은 유지합니다. 선택지 증가·제한 해제는 하나의 ADJUST_SOLVE입니다. 대기 증가에 기억 제한 5초를 추가 조건으로 붙이지 않습니다.

## 복원

판정 전 대기가 3초보다 크면 전체 복원은 대기 1초, 부분 복원은 0.5초만 줄입니다. 하한 3초에 닿아도 같은 결정에서 기억·풀이 복원까지 연속 수행하지 않습니다.

대기가 3초이면 기억·풀이 각각의 가장 최근 활성 단축 이력을 봅니다. 전체 복원은 해당 이력의 남은 단축량 전부, 부분 복원은 남은 단축량의 절반을 기억에서는 반올림, 풀이에서는 내림합니다. 실제 복원된 만큼만 잔량에서 차감합니다. 한 이력을 모두 복원하면 이전 이력은 **다음 하락**에 사용합니다.

| 상황 | 처리 |
| --- | --- |
| 기억·유한 풀이 복원 | 각각 최대 20·40초 |
| 판정 전부터 Ts=40이고 C=0~1 | 제한 해제. 해당 제한 기간의 활성 풀이 복원 이력 종료 |
| 이번 복원으로 Ts=40 도달 | 이번에는 40까지만. 제한 해제는 다음 C=0~1 판정 |
| 40초 최초 도입 후 C=2~3 | 40 유지. 도입 자체는 초 단위 단축 이력이 아님 |
| 풀이 제한 없음 | 없는 상태 유지 |
| 풀이 부분 복원 잔량 1초 | floor(1/2)=0. 잔량 1초 그대로 보존 |
| 선택지 증가로 제한 해제 | 이전 선택지 단계의 풀이 이력 종료. 기억 이력은 유지 |

복원은 고정 행동이며 밴딧 선택·보상으로 집계하지 않습니다. 복원 이벤트에 이력 ID와 실제 복원량을 남겨 중복 적용을 막습니다.

## 할인 UCB

유형별 독립적인 비맥락 밴딧을 사용합니다. 행동 우선순위는 KEEP → ADJUST_MEMORY → ADJUST_SOLVE입니다.

```text
discountFactor = 0.95
explorationCoefficient = 0.3
meanReward = rewardSum / effectiveCount
score = meanReward + 0.3 * sqrt(ln(1 + totalEffectiveCount) / effectiveCount)
p = 다음 유형별 유효 10문제의 첫 선택 정답 수 / 10
reward = max(0, 1 - abs(p - 0.8) / 0.8)
```

`totalEffectiveCount`는 해당 유형의 모든 행동 횟수 합계입니다. 선택은 실행 가능한 후보에만 수행합니다. 미시도 행동을 우선순위대로 선택하고, 학습 점수 동점도 같은 순서로 처리합니다.

과거 실제 적용 경험은 할인 횟수와 별도입니다. 적용된 선택이 모드 변경으로 보상 없이 종료될 수 있으므로 `hasEverApplied=true`, `effectiveCount=0`도 유효합니다. 미시도 행동을 먼저 처리한 뒤 이런 무보상 행동은 점수를 +∞로 취급해 0으로 나누지 않습니다. 양수 횟수에는 위 수식을 그대로 사용합니다. underflow로 횟수가 0이 되면 보상 합계도 0으로 정규화하고 같은 무보상 규칙을 적용합니다.

새 보상은 같은 유형의 모든 행동에 할인을 한 번 적용한 다음 선택 행동에 횟수 1과 보상을 더합니다. 고정 규칙이나 비교 모드에서는 할인·보상 갱신하지 않습니다. 수치 처리와 파라미터는 알고리즘 버전으로 기록합니다. 목표 80%는 게임 설계값이며 인지 향상이나 임상 효과를 주장하지 않습니다.

## 결정과 다음 결과의 연결

1. 묶음 B가 유효 10개가 되면 완료하고 B에 연결된 이전 밴딧 결정이 있다면 보상을 한 번 반영합니다.
2. 갱신된 학습값과 B의 통계로 다음 후보·선택을 계산해 결정 D를 `PENDING`으로 저장합니다.
3. 현재 화면 사이클에서 같은 유형이 더 나오면 기존 조건으로 출제합니다. 사용자 기록에는 남고 새 학습 묶음에는 포함하지 않습니다.
4. 화면 사이클 종료 트랜잭션에서 D를 `APPLIED`로 바꾸고 조건을 적용합니다. KEEP도 조건 값은 같지만 별도의 적용 결정입니다.
5. 이후 해당 유형의 첫 유효 문제부터 새 묶음 B2에 누적합니다. B2의 조건 버전과 적용 결정 D는 고정합니다.
6. B2 완료 시 D의 보상을 정확히 한 번 반영합니다. B가 자기 결정 D에 보상을 주거나 사이클 종료 전에 보상을 주면 안 됩니다.

초기 조건에는 적용된 밴딧 결정이 없어 첫 묶음은 과거 행동에 보상을 주지 않습니다. 고정·비교 결정의 결과도 기록하지만 밴딧 보상은 없습니다. 앱 재시작은 DB의 묶음·결정 연결을 그대로 복구합니다.

사용자가 진행 중인 게임을 명시적으로 끝내는 STOPPED도 그 화면 사이클의 종료 경계입니다. 이미 10개가 모여 대기 중인 결정을 적용하고, 미완성 묶음은 다음 게임으로 이어갑니다. 일시정지·홈 이동·앱 종료만으로는 적용하지 않습니다. 완료한 종합 게임 수에는 STOPPED를 포함하지 않습니다.

v1 기록은 원본을 모두 보존하되, 유형별 초기 조건·같은 생성 버전의 최근 최대 10개를 최초 보정 묶음으로 사용합니다. 10개 미만이면 새 기록과 이어서 모읍니다. 10개이면 최초 결정을 생성하고 진행 중인 게임이 있을 때는 끝날 때까지 적용을 미룹니다. 이 보정 묶음에는 이전 AI 결정이 없으므로 과거 보상을 소급 생성하지 않습니다. 선택 범위 밖의 기존 기록은 LEGACY_RECORD_ONLY로 남아 성적에 계속 포함됩니다.

## 종합 훈련

종합 훈련은 학습하기의 게임 시작 경로입니다. 배정은 색 4·그림 3·숫자 3 → 색 3·그림 4·숫자 3 → 색 3·그림 3·숫자 4로 순환합니다. 매번 순서를 주입된 난수로 섞고 계획을 저장합니다. 회전 기준은 **완료한 종합 사이클 수**이며 유형별 정식 훈련은 회전을 진행시키지 않습니다. 현재 화면의 세 유형 버튼은 연습이므로 학습 대상에서 제외합니다.

이어하기는 저장된 계획을 사용합니다. 무효 문항의 대체는 같은 슬롯·유형·조건을 유지하며 슬롯은 유효 문제 하나가 끝나야 채워집니다. 종합·유형별 훈련은 같은 유형의 미완성 묶음을 공유합니다.

예: 시작 전 색 묶음 8/10, 이번 종합에 색 4개라면 첫 두 색 문제로 묶음을 끝냅니다. 나머지 두 색 문제는 기록 전용이며 다음 묶음에 넘기지 않습니다. 조건 변경은 화면 사이클 끝에서 적용하고 다음 종합 또는 색 유형별 훈련에서 새 색 묶음을 이어갑니다.

## 비교 모드 경계

비교 규칙은 C=7~8에서 반올림 전 M/A 중 짧은 파트를 우선하고 동률은 기억 우선입니다. 우선 후보가 없으면 다른 후보를 검토합니다. C=9~10은 기억 후보 우선이며 복원·고정 유지 규칙은 동일합니다.

개발용 알고리즘 모드 전환은 화면 사이클이 진행 중이지 않을 때만 허용합니다. 새 `modeEpochId`를 만들고 미완성 묶음은 `CLOSED_BY_MODE_CHANGE`, 미보상 밴딧 연결은 `CANCELLED_BY_MODE_CHANGE`로 보존합니다. 이전·이후 문제를 합치거나 불완전 묶음으로 보상을 계산하지 않습니다. 기존 난이도·복원 이력·이미 획득한 밴딧 학습값은 유지하고 새 연결만 분리합니다.

단순 백그라운드 전환·앱 종료에서는 epoch를 바꾸거나 미완성 묶음을 닫지 않습니다. UI의 종합/유형별 **훈련 모드** 변경도 이 개발용 **알고리즘 모드** 변경과 다릅니다.
