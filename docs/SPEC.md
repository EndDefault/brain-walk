# 시니어 기억력 게임 앱 개발 지시문
## 1. 목표와 작업 원칙

Android 태블릿에서 인터넷 없이 실행되는 시니어 기억력 게임을 개발한다.


핵심 기능:


색·그림·숫자 기억력 훈련

세 유형을 섞은 종합 훈련

수행 기록과 홈 학습 현황

규칙 기반 후보 생성과 밴딧 기반 난이도 선택

모든 데이터와 AI 학습값의 기기 내부 저장


이 문서를 현재 명세의 기준으로 삼는다. 기존 프로젝트가 있으면 먼저 확인하고 사용자 변경을 보존한다. 충돌이나 구현 불가능한 조건은 임의로 변경하지 말고 이유와 수정안을 설명한다.


기능별로 구현·검증·커밋·PR을 나눈다. 전체 앱을 한 번에 구현하거나 하나의 커밋으로 저장하지 않는다.

추가 원칙:


호환되는 안정 버전을 확인하고 의존성 버전을 고정한다.

기존 프로젝트 이름·패키지명이 있으면 유지한다.

없으면 임시 앱 이름 MemorySteps, 패키지명 com.example.memorysteps를 사용한다.

Galaxy Tab A9+ 11인치를 화면 설계 참고 기기로 삼되, 실제 테스트 기기는 별도로 기록한다.

태블릿 가로 화면을 기본으로 설계하고 다른 화면 크기에서도 내용이 잘리지 않게 한다.

초기 버전은 기기당 한 사용자로 한다.

문자와 회전 그림은 확장 유형으로 분리하고, 첫 완성 범위는 색·그림·숫자 세 유형으로 한다.

## 5. 기본 게임 규칙

| 항목 | 규칙 |
| --- | --- |
| 화면상 한 사이클 | 10문제 |
| 초기 기억 시간 | 20초 |
| 기억 시간 범위 | 5~20초 |
| 다음 버튼 | 누르면 기억 단계를 즉시 종료 |
| 초기 대기 시간 | 3초 |
| 최대 대기 시간 | 10초 |
| 초기 선택지 | 4개 |
| 선택지 단계 | 4 → 6 → 9 → 12 → 16개 |
| 배치 | 열×행 기준 2×2 → 3×2 → 3×3 → 4×3 → 4×4 |
| 초기 풀이 제한 | 없음 |
| 풀이 제한 도입 | 40초 |
| 풀이 제한 범위 | 15~40초 |
| 답변 기회 | 최대 3회 |


진행:


대상을 보여준다.

기억 시간 종료 또는 다음 버튼 입력으로 대상을 숨긴다.

대기 카운트다운을 표시한다.

선택지를 표시하고 풀이 시간을 측정한다.

정답·3회 오답·시간 초과 중 하나로 문제를 종료한다.

결과 안내 후 다음 문제로 이동한다.


세부 동작:


풀이 시간은 선택지가 완전히 표시된 순간부터 측정한다.

오답을 눌러도 타이머는 초기화하지 않는다.

이미 선택한 오답은 다시 누를 수 없게 한다.

정답은 항상 하나만 존재해야 한다.

실제 정답 판정과 시간 측정에는 단조 증가 시계를 사용한다.

문제 중 화면을 벗어나면 진행을 멈춘다.

백그라운드 전환·앱 종료로 중단된 문항은 무효 처리하고, 재개 시 같은 조건의 새 문항으로 대체한다.

완료된 유효 문제는 유지하며 중복 저장하지 않는다.

## 6. 문제 소재

첫 버전:



| 유형 | 내용 |
| --- | --- |
| 색 | 제시한 색 또는 색 구성과 같은 보기 선택 |
| 그림 | 제시한 단순한 사물·도형과 같은 보기 선택 |
| 숫자 | 제시한 숫자 또는 숫자 조합과 같은 보기 선택 |


문제 생성은 규칙 기반으로 구현한다.


직접 만든 단순 도형·그림 또는 상업적 이용이 가능한 자료 사용

중복 선택지와 복수 정답 방지

선택지 증가 시에도 식별 가능한 크기 유지

16개를 만들기 위해 지나치게 비슷한 색만 추가하지 않기

각 유형의 구체적인 소재 구성과 문제 생성 버전을 기록하기


회전 유형을 추가할 경우 “방향이 달라도 같은 사물 찾기”로 별도 정의하고, 회전 대칭으로 정답이 여러 개 생기는 경우를 방지한다.


## 7. 유형별 훈련과 종합 훈련
유형별 훈련


선택한 유형으로 10문제를 진행한다.


종합 훈련

색·그림·숫자를 4·3·3개로 구성한다.

4개가 배정되는 유형은 사이클마다 순환한다.

문제 순서를 섞는다.

각 문제는 해당 유형의 난이도를 사용한다.

화면 사이클과 학습 묶음 구분


| 구분 | 단위 |
| --- | --- |
| 사용자에게 보여주는 사이클 | 유형별 또는 혼합 10문제 |
| 난이도 판단·AI 학습 묶음 | 같은 유형·같은 조건의 유효 문제 10개 |


종합 훈련과 유형별 훈련은 같은 유형의 누적 기록을 공유한다.


구현 규칙:


유형별 유효 문제 10개가 모일 때까지 해당 유형의 조건을 고정한다.

유형별 10개가 모이면 난이도 결정 결과를 대기 상태로 저장한다.

변경은 현재 화면 사이클 종료 후 적용한다.

현재 사이클에 해당 유형의 문제가 더 남아 있으면 기존 조건으로 출제하되, 이미 완료된 학습 묶음에는 중복 포함하지 않는다.

추가 문제는 사용자 기록에는 남기고, 난이도 판단·학습 포함 여부를 명시적으로 구분한다.

미완성 유형별 묶음은 앱을 종료해도 보존한다.

## 8. 기록 데이터와 계산 기준

| 기호 | 의미 |
| --- | --- |
| C | 학습 묶음 10문제 중 첫 선택 정답 수 |
| M | 첫 선택 정답 문제의 실제 기억 화면 노출 시간 평균 |
| A | 최종 정답 문제의 전체 풀이 시간 평균 |
| W | Σ(시도 횟수 × 전체 풀이 시간) ÷ 최종 정답 문제 수 |
| Tm | 현재 기억 제한 시간 |
| Ts | 현재 풀이 제한 시간 |
| P | 계산된 다음 풀이 제한 시간 |


계산 기준:


다음 버튼을 누르지 않은 문제도 실제 노출 시간을 M에 포함한다.

A, W는 두 번째·세 번째에 맞힌 문제도 포함한다.

전체 풀이 시간은 선택지 표시부터 정답까지의 누적 시간이다.

최종 실패 문제는 A, W에서 제외하되 실패와 시간 초과를 기록한다.

분모가 0이면 평균을 계산하지 않는다.

초 단위 반올림은 양수에서 0.5 이상 올림으로 통일한다.

W는 시도 횟수로 가중한 값이며 실제 제한 시간과 구분한다.


저장 항목:


유형, 문제 ID, 생성 버전

문제 조건 전체

실제 기억 시간과 다음 버튼 사용 여부

각 선택의 내용·정오·시각

첫 선택 정답 여부

최종 정답 여부와 시도 횟수

첫 선택까지 시간과 전체 풀이 시간

시간 초과·무효 여부

화면 사이클 ID, 학습 묶음 ID

적용한 AI 결정 ID

변경 전후 조건과 복원 이력

## 9. 난이도 규칙과 AI 역할

규칙 엔진은 실행 가능한 변경 후보를 계산한다. 밴딧은 허용된 후보 중 하나를 선택한다.



| C | 동작 |
| --- | --- |
| 0~1 | 고정 전체 복원 |
| 2~3 | 고정 부분 복원 |
| 4~6 | 유지 |
| 7~8 | AI가 유지·기억 조절·풀이 조절 중 선택 |
| 9~10 | AI가 기억 조절·풀이 조절 중 선택 |

한 번의 결정으로 하나의 행동만 적용한다.

실제로 변경할 수 없는 후보는 제외한다.

9~10개에서도 가능한 변경이 없으면 유지한다.

선택지 증가와 풀이 제한 해제는 하나의 풀이 조절 행동으로 취급한다.

과거에 논의한 “평균이 짧은 쪽을 항상 선택”하는 방식은 비교용 규칙 모드에만 사용한다.

## 10. 기억 조절 후보

| C | 후보 시간 |
| --- | --- |
| 7~9 | 반올림(M) |
| 10 | 반올림(M) − 1초 |


처리:


계산값을 5~20초로 제한한다.

현재 Tm보다 짧을 때만 변경 후보를 생성한다.

별도의 최대 감소 폭은 적용하지 않는다.


따라서 평균에 따라 시간이 크게 줄어들 수도 있다. 이는 현재 설계이며 임의로 추가 제한을 넣지 않는다.


## 11. 풀이 조절 후보
제한이 없는 경우


풀이 후보는 40초 제한 도입이다.


7~8개 정답이고 제한이 있는 경우


통과 조건:


W < Ts + 반올림(Ts / 2)


다음 시간:


P = 반올림(A) + 2초

조건 미충족이면 후보 없음.

P ≥ Ts이면 후보 없음.

P < Ts이면 아래 전환 규칙을 적용한다.

9~10개 정답이고 제한이 있는 경우

P = Ts − 5초


부담 점수 조건은 요구하지 않는다.


단계 전환


| 조건 | 풀이 후보의 결과 |
| --- | --- |
| P > 15초 | 풀이 제한을 P로 변경 |
| P ≤ 15초, 선택지 16개 미만 | 선택지 한 단계 증가 + 풀이 제한 해제 |
| P ≤ 15초, 선택지 16개·대기 10초 미만 | 풀이 제한 15초 + 대기 1초 증가 |
| P ≤ 15초, 선택지 16개·대기 10초 | 풀이 제한 15초 유지 |

전환은 풀이 후보가 선택됐을 때만 적용한다.

전환 시 기억 시간은 유지한다.

대기 증가에 기억 시간 5초를 추가 조건으로 요구하지 않는다.

현재 제한이 15초라는 이유만으로 자동 상승하지 않는다.

이전의 “부담 점수 10 이하이면 선택지 증가”는 사용하지 않는다.

대기 시간이 소수점이면 1초 증가 후 최대 10초로 제한한다.

## 12. 하락과 복원
대기 시간이 3초 초과


| C | 처리 |
| --- | --- |
| 0~1 | 대기 1초 감소, 최소 3초 |
| 2~3 | 대기 0.5초 감소, 최소 3초 |
| 4~6 | 유지 |


이 경우 기억 시간·풀이 제한·선택지는 유지한다.


대기 시간이 3초


| C | 기억 시간 | 풀이 제한 |
| --- | --- | --- |
| 0~1 | 최근 미복원 단축량 전부 복원 | 최근 미복원 단축량 전부 복원 |
| 2~3 | 최근 미복원 단축량 절반 반올림하여 복원 | 최근 미복원 단축량 절반 내림하여 복원 |
| 4~6 | 유지 | 유지 |


세부 처리:


기억 시간은 최대 20초.

유한한 풀이 제한은 최대 40초.

이미 40초인 상태에서 0~1개면 제한 해제.

제한이 없으면 없는 상태 유지.

40초 최초 도입 후 2~3개면 40초 유지.

절반 내림이 0초이면 변경 없음.

선택지 수는 하락 시 유지.

최근 단축량을 모두 복원하면 다음 하락에서 이전 미복원 이력을 사용.

복원한 값을 중복 적용하지 않음.

선택지 증가로 풀이 제한이 해제되면 이전 선택지 단계의 풀이 복원 이력 종료.

## 13. 밴딧 설계

첫 구현은 할인된 UCB 기반의 비맥락 밴딧으로 한다.


이 모델은 행동별 결과를 학습한다. 반응 시간 등은 후보 계산에 사용하며, 모든 지표를 입력받아 성공률을 예측하는 신경망처럼 설명하지 않는다.


행동

KEEP

ADJUST_MEMORY

ADJUST_SOLVE

학습 목표


다음 유형별 학습 묶음의 첫 선택 정답률을 80% 부근으로 유지하는 것을 초기 목표로 한다.


p = 다음 학습 묶음의 첫 선택 정답 수 / 10

reward = max(0, 1 - abs(p - 0.8) / 0.8)


80%는 게임 설계값이다. 인지 향상 효과나 임상적 적정 난이도를 증명하는 값으로 표현하지 않는다.


초기 설정

discountFactor = 0.95

explorationCoefficient = 0.3


유형별·행동별로 다음 값을 저장한다.


과거 선택 경험 여부

할인된 유효 선택 횟수

할인된 누적 보상

마지막 갱신 시각


갱신할 때 같은 유형의 행동별 횟수·누적 보상에 할인율을 적용한 뒤 선택 행동에 횟수 1과 새 보상을 추가한다.


UCB 점수는 다음 방식으로 구현하고 문서에 기록한다.


meanReward = rewardSum / effectiveCount


score =

    meanReward

    + explorationCoefficient

      * sqrt(ln(1 + totalEffectiveCount) / effectiveCount)

처음 시도하는 실행 가능 행동을 우선 한 번씩 선택한다.

초기 우선순위는 유지 → 기억 조절 → 풀이 조절로 한다.

실행 불가능한 행동은 초기 탐색에서도 제외한다.

학습된 점수 동률도 같은 순서로 처리한다.

고정 규칙에 따른 유지·복원은 밴딧의 선택으로 집계하지 않는다.

선택이 실제 적용된 다음 유형별 10문제로 보상을 계산한다.

동일 보상은 한 번만 반영한다.

앱 중단 시 미완성 묶음과 대기 중인 결정 연결을 보존한다.


데이터가 적고 행동의 실제 변경량도 달라지므로 개인화 효과를 보장하지 않는다. 선택·결과·학습값을 확인할 수 있게 한다.


## 14. 비교용 규칙 모드

AI와 비교할 기준 알고리즘을 개발 설정으로 제공한다.


7~8개: M, A 중 평균이 짧은 파트 우선.

평균이 같으면 기억 파트 우선.

우선 후보가 없으면 다른 후보 검토.

둘 다 없으면 유지.

9~10개: 동일한 후보 계산식을 사용하고 기억 후보 우선, 없으면 풀이 후보.

나머지는 같은 복원·유지 규칙 사용.


모드가 바뀌면 진행 중인 학습 연결을 혼합하지 않는다. 비교 모드의 결과를 AI가 선택한 결과로 학습시키지 않는다.


비교 지표:


목표 정답률과의 차이

큰 성적 하락 빈도

난이도 변경 횟수

실제 선택한 행동

유형별 차이


가상 테스트는 알고리즘 동작 확인용으로만 보고한다.

## 19. Git 저장소 운영

하나의 저장소에서 기능별 브랜치·작은 커밋·PR로 관리한다.


기존 Git 저장소와 원격 주소가 있으면 재사용.

저장소가 없으면 로컬 Git 초기화.

원격은 GitHub 공개(Public) 저장소 사용. 2026-09-22 사용자 승인으로 원문의 비공개 원칙을 변경한다.

원격 주소가 없으면 로컬 작업을 보존하고 주소 요청.

main은 검증된 상태로 유지.

기능 브랜치는 최신 main에서 생성.

의존하는 앞 PR이 병합된 후 다음 브랜치 생성.

사용자 변경을 임의로 폐기하지 않음.

강제 push, 이력 삭제, 자동 병합 금지.

저장소 공개 여부를 사용자 지시 없이 변경하지 않음.


빈 저장소에서 PR의 기준 브랜치를 만들기 위해 필요한 최소 초기 커밋만 main에 만들 수 있다. 이후 기능 개발은 브랜치와 PR로 진행한다.

실제 변경이 크면 PR을 더 나눈다. 각 기능의 테스트는 해당 PR에 포함하고 마지막에 몰아서 작성하지 않는다.


커밋 예시:


feat(records): 문제별 수행 기록 모델 추가

feat(records): Room 저장과 조회 구현

test(records): 중복 기록 및 재시작 복구 검증

docs(records): 저장 항목과 학습 포함 기준 정리


커밋은 파일별로 기계적으로 나누지 말고, 목적이 하나인 변경으로 구성한다.


## 21. PR 작성·병합

## 주요 결정

## 검증

미실행 항목과 이유


## 화면
UI 변경 시 스크린샷 또는 영상


## 남은 작업
관련 후속 작업과 알려진 한계

기능 브랜치에서 작은 커밋을 만들고 원격에 push한다.

초안 PR을 생성하고 구현·검증 결과를 갱신한다.

PR 생성 권한이나 도구가 없으면 동일한 본문 초안을 로컬에 준비한다.

검증 결과와 diff를 확인한 뒤 사용자 검토를 요청한다.

자동으로 병합하지 않는다.

기본 병합 방식은 Squash merge로 한다.

PR 안에는 세부 커밋을, main에는 기능별 정리된 커밋을 남긴다.
