# 결정 기록

## 2026-09-22 · 첫 PR

- **공개 저장소 사용:** 사용자 후속 지시가 최초 명세의 비공개 원칙보다 우선합니다. `EndDefault/brain-walk`를 Public으로 유지합니다.
- **원격 초기 이력 유지:** 기존 `main`의 `aa4e485`는 README만 포함한 초기 커밋입니다. 이를 부모로 사용하며 기존 `.idea/` 파일은 삭제하거나 변경하지 않습니다.
- **첫 PR 범위:** 빌드·기본 실행·홈 빈 상태·이용 안내·화면 이동 확인까지입니다. 훈련 유형 카드는 안내이며 누르는 버튼이 아닙니다. 게임 시작, 그래프, 가짜 성적은 제공하지 않습니다.
- **이름:** 기존 앱이나 Android 패키지가 없어 명세의 임시 프로젝트 이름 `MemorySteps`, 패키지 `com.example.memorysteps`를 사용합니다. 저장소 이름 `brain-walk`는 유지합니다. 화면에는 한국어 이름 ‘기억 산책’과 MemorySteps를 함께 표시합니다.
- **커밋 단위:** 기준 명세, 빌드 설정, 기본 화면, 실행 검증·문서를 목적별로 구분합니다. 무관한 파일을 섞거나 파일 수만을 기준으로 나누지 않습니다.
- **Android 버전:** 초기 최소 지원은 API 26(Android 8.0)입니다. compile/target API 36, Build Tools 36.0.0으로 고정합니다. 실제 사용자 기기는 아직 확인되지 않았습니다.
- **호환되는 안정 버전 고정:** 설치된 SDK 36과 검증 가능한 AGP 8 계열에 맞춰 AGP 8.13.2, Gradle 8.14.4, Kotlin 2.2.21, Compose BOM 2026.02.01, Activity 1.12.4, Navigation 2.9.8을 선택합니다. 최신 버전을 자동 추적하지 않습니다. Compose compiler plugin과 Kotlin 버전은 일치시킵니다.
- **JDK:** Gradle 실행은 설치된 Corretto 21, Java/Kotlin 출력은 17로 통일합니다. PC별 JDK 절대 경로는 저장소에 넣지 않습니다.
- **Windows 한글 경로:** 사용자 작업 경로를 유지하기 위해 `android.overridePathCheck=true`를 사용하고 실제 빌드 결과로 확인합니다.
- **가로 화면 우선:** 태블릿 가로 화면에서는 두 열, 작은 화면과 글자 확대에서는 한 열로 배치합니다. 회전을 강제 고정하지 않고 시스템 방향과 창 크기에 적응합니다. 모든 내용은 스크롤할 수 있고 버튼은 최소 64dp입니다.
- **로컬 저장 원칙:** 네트워크 권한과 서버 SDK를 추가하지 않습니다. 백업을 비활성화합니다. Room/DataStore 및 민감하지 않은 학습 기록의 명시적인 백업 정책은 저장 기능 PR에서 구체화합니다.
- **외부 자산:** 폰트는 기기 기본 폰트, 앱 아이콘은 직접 작성한 VectorDrawable입니다. 다운로드한 이미지·음원은 없습니다.
- **개발 통합 브랜치:** 사용자 후속 지시에 따라 개발 중인 PR의 대상은 `develop`으로 변경합니다. 기능·문서 브랜치는 최신 `develop`에서 만들고 해당 브랜치로 PR을 보냅니다. 기존 원격 `develop`은 초기 `main`과 같은 커밋에서 시작합니다. PR #1도 `develop`을 대상으로 변경합니다.
- **완성본 반영:** `main`에는 앱 완성 및 최종 검증 후 별도 PR로 반영합니다. 개발 중간 결과는 `develop`에 모읍니다.
- **다음 단계:** 본 PR 검토·병합 후 최신 `develop`에서 문서 PR을 시작해 난이도 규칙 예제, 복원 이력, AI 보상 연결, 데이터 트랜잭션을 구체화합니다. 자동 병합하지 않습니다.

## 2026-09-22 · 설계 문서 PR

- **사용자 요청:** 구현·검증·목적별 커밋·PR은 합의한 범위에서 이어서 진행합니다. 앞 PR이 develop에 병합된 뒤 다음 기능 브랜치를 만들며 자동 병합은 하지 않습니다.
- **디자인 선택:** 사용자가 ‘차분한 기록형: 절제된 색상, 학습 기록과 진행 상황 중심’을 선택했습니다. 현재 홈은 임시안이며 파스텔 카드 반복과 감성 문구 중심 구성을 변경합니다. 실제 화면 수정은 게임 화면·홈 PR에서 적용하고 이 PR은 문서만 변경합니다.
- **종합 훈련 재확인:** 홈에서 직접 시작하는 주요 경로로 제공합니다. 혼합10문제(4/3/3),4개 유형 순환, 유형별 난이도·누적 묶음 공유를 유지합니다. 유형별 훈련도 함께 제공합니다.
- **회전 기준 구체화:** 완료한 종합 사이클 수를 기준으로 색→그림→숫자가4개 배정을 받습니다. 중단·재개와 유형별 훈련은 순환 카운터를 증가시키지 않습니다.
- **복원 해석:** 부분 복원은 최신 이력의 원래 단축량이 아니라 현재 남은 단축량을 기준으로 합니다. 한 번의 하락은 축별 최신 이력 하나까지만 복원합니다. 대기3초 도달이나 풀이40초 도달 후 후속 복원/제한 해제는 다음 판정에서 처리합니다.
- **보상 없는 선택의 점수:** 실제 적용 경험이 있지만 모드 전환으로 보상 없이 종료되어 유효 횟수가0이면, 미시도 행동 탐색 후 +∞ 점수로 평가합니다. 양수 횟수의 UCB 수식은 명세 그대로입니다. underflow 처리도 AI_DESIGN.md에 기록했습니다.
- **알고리즘 모드 변경:** 진행 사이클이 없을 때만 적용합니다. 새 epoch를 만들고 미완성 묶음·미보상 연결은 종료 상태로 보존합니다. 기존 기록·난이도·복원 이력·획득한 밴딧 학습값은 유지합니다. 종합/유형별 훈련 변경에는 이 분리 규칙을 적용하지 않습니다.
- **풀이 마감 경계:** 단조 시각이 마감 미만일 때 답변을 처리하고, 마감 이상이면 시간 초과로 판정합니다. 콜백 도착 순서나 UI tick 횟수에 의존하지 않습니다.
- **저장 책임:** DataStore에는 안내·효과음 설정을 두고 학습 연결에 영향을 주는 실제 알고리즘 모드는 Room epoch로 관리합니다. 문제·묶음·보상·마지막 문제의 사이클 완료를 같은 트랜잭션에서 처리합니다.
- **다음 PR:** 순수 Kotlin 문제 모델·세 유형 생성·고유한 정답·최대3회 판정·주입 시계/난수와 재현 가능한 테스트를 구현합니다. 혼합 사이클·기록 저장·난이도·밴딧은 각각의 예정 PR에서 연결합니다.
